方案名《你叫什么名字 / What's Your Name》
作者YPQ
日期2026-09-11
一句话 logline万圣节夜，一个来要糖的小女孩站在你家门口。你不认识她——而她是为了你以前做过的一件事来的。

1. 核心概念

电梯陈述

万圣节夜，你是一个独居的男人。你听见门铃，开门，门外站着一个来要糖的小女孩。

你可以和她说话——但你的每一句话都在推动一根你看不见的张力。推得太轻，她什么都不说；推得太重，你就死。你要从她的话里找出那些互相矛盾的地方，把它们一块一块拼起来，直到拼出一件事：她认识你，而你不认识她。

而她之所以站在这里，是因为你以前做过的某件事。

核心体验

  • 分寸感：你不是在挑"正确答案"，你是在控制压力的大小。每一次开口都是一次冒险。
  • 拼图感：故事是碎的，碎片在你手上。没有人会替你把它拼回去。
  • 迟到的明白：游戏结束之后你才会反应过来，刚才你随口说的那一句，到底意味着什么。

2. 主题契合（破碎的故事 / 不可靠叙述）

如何体现主题

男人是"不可靠叙述者"里最纯的一种：他不是骗子，他说的每一句话他都真的相信。

玩家会本能地信任一个没有恶意的人——而这份信任本身就是陷阱。撒谎的人会被抓住；真诚的人不会被怀疑。

同时女孩也在说谎，但她的谎言是保护性的：真相说破了，他会崩。于是三个信息来源（男人、女孩、房子）各说各话，玩家永远无法确认哪一个是全真的。"你不知道该相信什么"就是本作的恐怖所在。

落在哪个机制上

  • 男人不可靠 → 落在张力轴上。

他是玩家的"嘴"，但他没有任何可陈述的事实，所以玩家只能问和连，不能说。他的无知不是设定，是机制的一部分——从设计上就不存在"男主角说了一句他知道的话"这种漏洞。

  • 女孩不可靠 → 落在碎片拼接上。

同一个细节她前后会改口，而她改口的地方，就是那块"不能同时为真"的碎片。

  • 故事是碎的 → 落在笔记本上。

玩家每一次成功拼接，都是在亲手重构一个被讲坏了的故事。主题不靠台词说，靠手上的动作做。

  • 玩家开始怀疑信息的时机：Round 1 结尾——他给出糖果、她道谢离开、灯灭，然后画面安静地回到门口。

玩家会以为自己通关了。就在那一刻，他第一次意识到：刚才那一切可能根本不成立。这是全片怀疑的起点，也是整个游戏最重要的一次转折。

3. 核心玩法

  • 目标 / 失败条件：
    • 目标：收集足够多的碎片（建议 6 条），把它们拼接对齐，并在时机成熟时停止"给糖"这个动作、说出从环境里找到的那句话。
    • 失败 ①：张力进入危险区 → 死亡演出（2–3 秒），回到本轮开头。
    • 失败 ②：耐心耗尽 → 她安静地离开，进入循环结局。
  • 核心循环：采集 ↔ 拼接。

采集在门口，高张力、有代价；拼接在笔记本，零张力、零惩罚。紧张 → 安全 → 紧张。笔记本是 8–12 分钟里唯一的休息区。

  • 操作方式：

读取对话选项 → 选择一个开口的力度 → 观察她的表情、环境音与糖纸声来判断张力 → 回到笔记本拖拽碎片配对 → 解锁新问法 → 再回门口用它。

  • 参照物：
    • 机制近亲：Her Story、Return of the Obra Dinn（碎片拼接、主动推理）
    • 语气近亲：Mouthwashing、Memento（真诚的、不撒谎的不可靠叙述者）
    • 差异在于：本作的压力不来自时间或点击次数，而是来自"你刚才那句话说了多重"。

单局节奏

段落时长玩家状态
开场（三选一，无教程教学）~40 秒好奇、放松
Round 1 采集 + 首次拼接~2 分钟学会"分寸"这件事
Round 1 假结局（给糖 → 灯灭 → 回到门口）~20 秒第一次怀疑
Round 2 采集（她改口、环境变了）~3 分钟警觉，开始主动看房子
Round 3 采集（起点张力高、操作空间窄）~3 分钟紧绷，必须精准
终局（说出那句话 / 拒绝给糖）~1 分钟释然，或后悔

4. 叙事与呈现

故事梗概

万圣节夜里，一个独居男人开门，见到一个来要糖的小女孩。他以为这只是个普通的万圣节。

女孩不是路过。她认识这栋房子——她知道他家的狗叫什么，她知道第几级台阶会响，她知道门铃是坏的。她每说错一次，就露出一个新的错处；而他每一次都能给出一个真诚的、合理的解释，因为他真的不知道。

他不是在隐瞒。他是真的一点都不记得。

玩家要在"这只是个小孩"和"事情不对"之间反复横跳。他每拼成一块碎片，就把这个夜晚重新理解一次。真相不在任何人的嘴里——它刻在门框上那道停了很多年的旧刻痕里，烂在门廊那只南瓜灯上刻着的名字里。

「不可靠」机关设计

三层不可靠，各落在不同的机制上：

层谁不可靠怎么不可靠玩家怎么察觉
1男人他不是撒谎，是他对整个夜晚的理解框架错了玩家发现自己比他早一步明白
2女孩她改口、回避，因为她不能让他崩同一细节前后不一致 → 一块可拼接的碎片
3叙事本身游戏的第一句话就是男人脑补的真结局时，同一位置换成她真正说的那句话

第 3 层是本作最锋利的一处：开场那句台词其实是他的想象，她当时根本没说要糖。改一行台词的成本，换全片最重的一击。

  • 叙事载体：单场景门口对话 + 玩家笔记（跨循环唯一留存的东西）+ 环境物证。

不做闪回、不做旁白交代、绝不让任何 NPC 替玩家把真相说出来。

  • 结局设计：
    • 真结局「你叫什么名字」：集齐碎片 + 从环境里拿到那个名字 + 在正确的时机停止"给糖" → 玩家听到她真正说的第一句话。她不再是小女孩，也不再是怪物。
    • 循环结局「第 N 年」：给糖。她道谢离开，字幕打出：第 [N] 年。最容易拿到的结局，也是叙事的陷阱。
    • 崩溃结局「说早了」：碎片不足时强行指认 → 恐怖演出 → 死亡。
    • 另有 8–10 个死亡结局，对应各个雷区，每个 2–3 秒。

5. 体量控制

  • 预估游玩时长（分钟）：首通 8–12 分钟；全结局 20–30 分钟。
  • 场景 / 关卡数量：1 个场景（门口 / 门廊），3 个状态变体（正常雨夜 → 细节改变 → 灯坏雨停）。不做第二场景。
  • 必须有（MVP）：
    • 1 个对话场景 + 女孩立绘（4 个表情即够用）
    • 张力轴（三条反馈通道至少要有其中一条可读）
    • 碎片拼接笔记本（可配对、可对齐）
    • 8 条可收集碎片
    • 2 个结局（真结局 + 循环结局）
    • 3 个死亡结局
    • 浏览器可玩
  • 最好有：
    • 6 个表情差分、第三反馈通道（糖纸声）、崩溃结局、环境道具每轮变化、真结局的"真实第一句"演出
  • 可以没有：
    • 音乐、成就、存档、多语言、设置菜单、任何选项页、过场动画

底线版本

如果只剩 7 天：砍到 Round 1 + Round 3 两轮、5 条碎片、1 个真结局 + 1 个循环结局、3 个死亡、女孩 3 个表情、音效只有雨声和糖纸声。

这个版本仍然满足全部硬性要求：是恐怖游戏、在一个房间里、围绕万圣节、≤10 分钟、可玩可通关。
它只是变短，不是变成半成品。

  • 不做清单：
    • 不做 3D、不做第一人称移动、不做多场景
    • 不做语音；逐字打字机效果可以
    • 不做存档系统（状态放内存即可）
    • 不做自定义着色器、不做体积雾之类的高成本氛围
    • 不做战斗、追逐、QTE
    • 不做任何需要 3 人以上投入的内容

6. 美术与音频

  • 视觉风格：简化 2D 手绘，单张门口场景 + 女孩立绘。

明确不做 3D——三周里 3D 会吃掉一半工期，而恐怖靠的是构图和节奏，不是多边形数。
建议走"低饱和、强对比、雨夜单一光源"的路线：让走廊灯成为画面里唯一的亮部。

  • 素材来源：
    • 优先团队原创（手绘 + 自己录的环境音）
    • 外部素材只使用 CC0 / CC-BY / OFL 等明确授权的协议，并建立 CREDITS.md 逐条登记（资产名 / 来源 URL / 作者 / 协议）
    • 禁用任何 AI 生成素材（图像、音频、字体）——这是赛事的零容忍红线
    • 禁用任何未授权同人素材
  • 音频方向：少即是多。底噪只有雨声；Round 3 把雨声也停掉，用"静"做恐怖。

关键音效只有几件：门铃、糖纸、走廊灯电流、骤静。音乐建议只有一段极简 drone，其余全部留白。

  • 美术最大工作量：背景的 3 个状态变体。

同一个门口要画出三种差异（南瓜更烂、刻痕多一道、灯全灭），既要看得出"是同一个地方"，又要一眼看出"变了"。这是全片最难的美术任务，建议最早开工。

7. 技术风险（不指定引擎与语言）

不确定的技术点

  1. 网页音频：浏览器普遍要求用户先有一次交互才能播放音频。开场必须有明确的"点击开始"，否则玩家会在静音里玩完前 30 秒。
  2. 网页包体积：资源压缩不当会让加载时间变长。投票期评审的耐心可能只有几十秒。
  3. 网页端的输入响应：碎片拖拽在不同浏览器上的一致性需要实测。
  4. 状态规模：碎片、张力、耐心、轮次、雷区标记——状态一多，就容易出现"某个组合下卡死"的隐性问题，而且很难在试玩中撞到。

先做什么验证

先做"最难的那一点"：一条完整的碎片闭环。

即：在门口问出一句 → 笔记本里出现两块碎片 → 拖拽对齐成立 → 解锁一条新问法 → 回到门口真的用上它。

这一条跑通了，整个游戏就成立；跑不通，就必须改机制。

这是第一个原型唯一要证明的事——不做美术、不做音效、不做第二场景、不做结局。

替代方案

  • 若网页音频 / 体积问题无法在预算内解决 → 转为桌面可执行包（赛事同样接受），网页版降为可选。
  • 若拖拽在网页端不稳 → 把"拖拽配对"降级为"点两块碎片 → 点确认"。功能等价，实现成本更低。
  • 若张力三通道做不全 → 只保留"她的表情"这一个通道，其余作为加分项。
  • 若张力轴整体调不出手感 → 退化为明示的三档选择"轻 / 中 / 重"（见第 12 节）。

8. 团队与分工

  • 需要几人：3 人
  • 角色需求：
    • 1 名程序（每天 2–3 小时，是本项目的产能瓶颈）
    • 1 名美术（负责背景 3 个变体 + 女孩表情）
    • 1 名编剧（负责全部面向玩家的文字）
  • 我能承担：（待填）
  • 缺什么角色：音频是当前最薄弱的一环。

建议由美术或编剧兼任，只做 4–6 个关键音效；若无人能胜任，就把音效压缩到"雨声 + 糖纸声 + 骤静"三件套——这三件已经足够撑起全片。

12. 风险与 Plan B

  • 最大风险：男人的台词露馅。

本作的设定极其脆弱——他是"真诚的不可靠叙述者"，只要他有一句台词带出暗示、反讽或欲言又止，整个反转当场失效，玩家会提前猜到，游戏从"可怕"变成"故弄玄虚"。
缓解：编剧四条铁律（每句话都是真诚的困惑 / 选项的知情度必须和他的状态严格同步 / 女孩的谎言必须有善意 / 绝不让 NPC 替玩家说破），加编剧交叉互审。

Plan B

  • 若张力轴调不出手感（玩家读不出来、死亡总像是被冤枉）→ 退化为明示的三档选择："轻 / 中 / 重"，把隐性状态变成显性选择。会失去一部分微妙感，但保证可玩。
  • 若碎片拼接的推理量超出 8 分钟能承受的范围 → 碎片从 8 条砍到 5 条；拼接改为"系统提示哪两块可以试"。
  • 若内容量做不完 → 执行第 5 节的底线版本（两轮、5 条碎片、2 个结局）。

何时放弃

  • 10-01 之前，若"一条完整的碎片闭环"仍未跑通 → 放弃碎片拼接，改为"直接的对白选择 + 张力轴"。这是唯一一个"晚于这时就不能再保"的系统。
  • 10-01 当天，若可玩版还不能在浏览器里跑完一轮 → 停止加任何内容，把剩余时间全部用于让现有两轮稳定可通关。

13. 差异化

  • 一句话说服队友：别的"不可靠叙述者"游戏让你去抓别人的谎——我们让你去抓自己刚刚说过的一句话，而你已经不记得自己说过了。

最大不同

  1. 玩家是"压力调节器"，不是"选项挑选器"。

死亡不是因为选错，是因为推得太狠。责任在玩家身上——所以可学习、可进步，不是猜谜。

  1. 主题落在手上，不在台词里。

"破碎的故事"没有被讲出来，而是被做成一个要动手拼的东西。

  1. 开场第一句台词就是谎言。

玩家要到真结局才会发现，游戏的第一句话是男人自己脑补的——她当时什么都没说。
