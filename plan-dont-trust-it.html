① 共用底座 · 三个人都先读这一段

三条已经锁死、谁也不要再讨论的设定

  1. 只有一个键：指认。没有第二个交互键，没有移动以外的其他操作。
  2. 它的话只有三类：真的（不按）／假的且有害（按）／荒谬但无害（不按，按了就错）。 第三类是核心——骗你按错的那一类，价值比前两类都高。
  3. 不按 = 那句话成真，直接改变游戏状态；按错只有提示音、没有惩罚；唯一的约束是 CD。
这三条是"判据不是真假，是恶意"这句话的全部机制承载。任何交付物如果让玩家能靠"这句话听起来假不假"取胜， 那就跑偏了——正确的技能是分清「它在胡说」和「它在害你」。

9/18 – 9/21阶段 1 · 原型文案：先写能验证规则的那 3 句XJW

原型的目的只有一个：验证"玩家能不能自己搞明白什么时候可以按"。所以这 3 句不是随便挑的，必须是三种类型的最标准样本。

这 3 句的构成（硬性）

类型作用写作要求
1 句 真建立基线：它大部分时候说的是真的平淡、无害、像闲聊
1 句 假害提供"必须按"的样本后果要立刻看得见（门锁、灯灭）
1 句 胡说最关键：让玩家体验"按了就错"荒谬到一听就不对，但毫无威胁——它是在骗你去否认
写作时的自检问题：把这三句连续读出来，一个没读过方案的人听完，会不会以为"听起来有问题的就该按"？ 如果会，说明 胡说 那句还不够安全、或者 假害 那句不够危险——要重新写，不是调参数。

验收标准

  • 3 句按上表构成，已填进判定点表
  • 盲测中记录到玩家的原话：他有没有问"我该怎么按"
  • 如果玩家在 胡说 那句上毫不犹豫地按了，记录为"分类不可辨"，交给 YDC 决定是改文案还是改机制
9/22 – 9/25阶段 2 · 内容写作：8–10 分钟的全量台词XJW9/25 冻结

工作量参考（按 8–10 分钟）

以"每句 3–5 秒 + 句间留白 1–2 秒"估算，全程大约需要 80–120 句台词，其中判定点约 20–30 个。 三类话的配比建议：真的 ≈ 60–70%（信任是基础）、假害 ≈ 15–20%、胡说 ≈ 15–20%。

为什么"真的"必须占大多数：方案书里写得很清楚——"它的叙述大部分是真的，所以信任是真的，背叛也是真的"。 如果假话比例一高，玩家会进入"每句都怀疑"的模式，游戏就退化成猜硬币了。

分幕写作要求

幕它想达到的目的玩家应该体验到
第一幕（约 2–3 分钟）让你习惯听它说话、习惯它的语气"这东西好像只是在跟我聊天"
第二幕（约 3–4 分钟）让你失去行动的余地——它开始在你 CD 冷却时说话"我明明知道该按，但我按不了"
第三幕（约 3 分钟）摊牌：它不再掩饰目的"原来它要的不是骗我，是不让我动"

第二幕是全场唯一的紧张来源（CD）。写作时要有意识地安排"连续判断点"——两句话挨得很近，玩家只能救一个。

结局分档（机制上为"判断结果分档"，不做分支树）

  • 建议 3 档：判断准确率高 / 一般 / 低。档数越多，收尾文案越多，而玩家只会看到一档——不建议超过 4 档。
  • 每档需要写：触发条件（用哪个累计值、阈值多少）+ 300 字以内的收尾文案 + 画面表现（用已有的哪张图/哪个音效）。
  • 三档的差别要落在"你最后剩下什么行动能力"，而不是"字幕说了什么好话"。

验收标准

  • 判定点表全量填完，编号连续、分类 列只有三个合法值
  • 每一条 后果-不按 都能在画面上被看见
  • 三类话配比落在建议区间内（偏差可在评审时说明理由）
  • 9/25 当天把这份表标为"冻结版"并发给全组

③ YPQ · 美术的完整计划 视觉素材 + 音频 + 授权台账

一句话定义你的岗位

这个游戏是靠声音和文字吓人的游戏，所以音频不是配角，是本作工作量最大的一块。 视觉这边则相反——方案从设计上就把美术压到了最低（无动画、无手绘、低分辨率）。

9/18 – 9/21阶段 1 · 采购 + 原型占位（音频先动）YPQ
为什么音频排第一：Freesound 必须登录才能下载，站内试听只是低码率预览， 批量抓取被 ToS 明文禁止，站点还会间歇 503。必须提前归档，不能临场现搜。

本阶段任务（按顺序）

  1. 音频先行：环境底噪 + 点缀音 + 反馈音（按对/按错）+ 打字机音 + 句末音，下载到本地并归档。
  2. 判定"每句台词配不配语音"（9/18 前给结论）。这是本周四件必决事项之一，不能给"应该能拿到"这种答案—— 要给的是实际到手的文件 + 实测时长 + 授权确认。
  3. 房间 tileset 定稿：先定一套，别比价到 9/25。风格定下来之后 UI 和道具才有的配。
  4. UI 套件：文本区（建议裸文本、不加边框）、CD 指示器、对错反馈、标题/结束画面。
  5. 给 YDC 占位素材：灰盒阶段用纯色 32×32 方块就够，命名按规范（这样替换时零改动）。

音频先动的理由（给不清楚背景的人）

  • 它是唯一"依赖外部站点 + 需要登录 + 会临时不可用"的环节，风险最高。
  • 它是程序的关键路径：每句台词的音频时长，直接决定打字速度、判定点留白和 CD 是否成立。
  • 它最花时间：15–20 个文件，每个都要试听、核对许可、改名、转码。

验收标准

  • 环境底噪与按对/按错音已到手并通过试听（两者音色能明确区分）
  • 语音可行性有明确结论（有文件 / 没有），已通知 XJW
  • 占位素材已按 ID 命名交付给 YDC

9/26 – 9/28阶段 3 · 接入配合与观感调优YPQ
  • Godot 音频导入设置：环境底噪必须设为循环；点缀音要能随机播放；打字机音要能高频叠放（不能有几百毫秒延迟）。
  • shader 只用一块全屏 ColorRect + 一个 shader（颗粒/暗角），避免多个全屏效果互相踩（多个 hint_screen_texture 会互相覆盖）。
  • 氛围手段（零素材成本，效果最好）：2D 里可用 CanvasModulate 整体调暗 + 点光源轻微抖动 + 噪点 + 静音瞬间。（点光源抖动是氛围性价比最高的一招，但记得用 YDC 确认的节点方式。）
  • 音量平衡：环境音不能压过打字机音；跳吓音要明显高于底噪但不要爆音。

验收标准

  • 在 YDC 的构建包上试听完整一局，没有一声"听不见/太吵/循环处有咔哒"
  • 暗角/颗粒在最终分辨率下不糊、不闪

  • Windows 可运行（导出 .exe 并在一台干净机器上试跑过）
  • 投稿期内才开始开发（没有拿旧项目）
  • 素材全部合法授权：无盗用、无未授权同人、无"personal use only"、无 CC-BY-NC / GPL / CC-BY-SA
  • 全程无任何 AI 生成内容（美术／音频／文本／代码）
  • 不做任何 AI 语音、不克隆任何人的声音
  • 非 18+ NSFW；投票期免费、人人可玩
  • 使用官方标签 #HawktoberHorrors
  • ⚠️ 提交前亲眼逐条读 itch 页面的 Rules 原文（不靠转述）
  • ⚠️ 2026 明确不提供任何延期——内部 9/30 提交，留 3 天缓冲

本页之外还需要团队定夺的事
